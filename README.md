# Network Router

A macOS daemon that sends traffic for configured domains and IP ranges over iPhone USB tethering. All other traffic keeps the system default route, usually Wi-Fi.

The behavior is specified in [docs/specs/network-router-project-spec.md](docs/specs/network-router-project-spec.md).

## Install

```bash
git clone https://github.com/tunglt1810/network-router.git
cd network-router
sudo make install
```

The installer:

1. Builds the binary and copies it to `/usr/local/bin/network-router`.
2. Copies `config.yaml` to `/usr/local/etc/network-router/config.yaml`. An existing installed config is backed up first.
3. Creates the state directory `/usr/local/var/network-router/`.
4. Registers and starts the LaunchDaemon `com.bez.network-router`.

The tray icon is opt-in:

```bash
network-router tray-enable    # register and start the tray icon
network-router tray-disable   # stop and unregister it
```

To reinstall after a code change:

```bash
sudo rm -rf build && make build && sudo make reinstall
```

## Configure

Edit `/usr/local/etc/network-router/config.yaml`:

```yaml
# Domains routed over the phone. A resolver file covers the whole subtree,
# so 'example.com' and '*.example.com' are equivalent.
tether_domains:
  - 'github.com'
  - '*.githubcopilot.com'

# IP ranges routed over the phone. Bare IP addresses belong here.
tether_cidrs:
  - '91.108.4.0/22'
  - '34.2.135.176/32'

# Optional. A service name from `networksetup -listallhardwareports`,
# not a device number such as en7. Default: iPhone USB.
# phone_interface_name: "iPhone USB"

# Optional. Fallback resolvers, each routed over the phone.
# Default: 1.1.1.1:53 and 8.8.8.8:53.
dns_upstream_pinned:
  - 1.1.1.1:53
  - 8.8.8.8:53
```

The daemon reads the config only when it starts. After an edit, restart it:

```bash
sudo launchctl kickstart -k system/com.bez.network-router
```

## Commands

| Command | Effect |
| --- | --- |
| `network-router status` | Show routing state, the phone interface, the route count, and whether the DNS proxy runs. |
| `network-router on` | Turn routing on. Routes are applied now, or when tethering becomes ready. Aliases: `enable`, `apply`, `restart`. |
| `network-router off` | Turn routing off and remove the routes. Routing stays off until `on`. Aliases: `disable`, `clear`. |
| `network-router refresh` | Resolve the domains again and re-apply the routes. |
| `network-router tray-enable` / `tray-disable` | Register or remove the tray icon. |

The commands do not need `sudo`.

## Tray

| Icon | Meaning |
| --- | --- |
| Green | Routing is on and routes are applied. |
| Gray | Routing is off, or tethering is not ready. |
| Red | The daemon does not answer. |

The menu has the status, **Turn Routing On/Off**, **Refresh Routes**, **Show Debug** (opens `tail -f` of the daemon log in Terminal), **Hide Icon**, and **Quit**. **Hide Icon** makes the icon transparent. Its menu bar slot stays clickable, so you can open the menu to show the icon again.

## Troubleshooting

Logs:

```bash
tail -f /var/log/network-router.log    # daemon
cat /tmp/network-router-tray.log       # tray
```

Routes are not applied:

```bash
network-router status                  # read "Phone reason"
networksetup -listallhardwareports     # find the phone service name
netstat -rn -f inet                    # routing table
```

A tethered domain does not resolve. The proxy is the only resolver for the configured domains, so a proxy problem shows as a connection failure:

```bash
sudo lsof -nP -iUDP:5454 -iTCP:5454              # is the proxy listening?
dig @127.0.0.1 -p 5454 <configured-domain> A     # ask the proxy directly
grep -E "Resolution failed|system resolver" /var/log/network-router.log | tail
```

The daemon removes its resolver files when it stops and again when it starts. To remove them by hand:

```bash
sudo grep -l "# Generated by Network Router" /etc/resolver/* | xargs sudo rm
sudo killall -HUP mDNSResponder
```

The daemon is not running:

```bash
sudo launchctl print system/com.bez.network-router | head
sudo launchctl bootstrap system /Library/LaunchDaemons/com.bez.network-router.plist
```

## Uninstall

```bash
sudo make uninstall
```

The uninstaller removes the routes, the resolver files, both launchd jobs, and the installed files. It keeps `/var/log/network-router.log`.
